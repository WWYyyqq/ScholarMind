## 7. 核心理解

### 7.1 Supervisor 为什么委派

Supervisor 是研究经理，不直接搜索。它把复杂问题拆成多个独立
`ConductResearch`，使每个 Researcher 有较短、聚焦的上下文，并允许多个方向
并行。每轮结果回来后，Supervisor 再决定补查还是调用 `ResearchComplete`。

### 7.2 Researcher 为什么压缩

搜索页面、工具输出和模型消息会快速增长。如果全部交给 Supervisor：

- 上下文容易超限；
- 多个 Researcher 的噪声会叠加；
- Writer 难以识别稳定输入。

Compression 形成 `compressed_research` 作为跨子图接口，同时把工具和 AI 原始
内容保存到 `raw_notes`。

### 7.3 两层并行

本项目没有使用 LangGraph `Send` 做并行，而是在节点内部使用
`asyncio.gather`：

1. Supervisor 同一轮的多个 Researcher 并行；
2. Researcher 同一轮的多个搜索/MCP Tool Call 并行。

结果顺序与输入 Tool Call 顺序一致。

### 7.4 Reducer

- `messages` 使用 `MessagesState` 的消息合并；
- `researcher_messages` 使用 `operator.add`；
- `supervisor_messages`、`notes` 和 `raw_notes` 使用 `override_reducer`；
- `override_reducer` 默认追加，只有 `type=override` 时覆盖。

## 8. 新发现的技术债

### 8.1 Supervisor 异常条件永远成立

```python
if is_token_limit_exceeded(e, configurable.research_model) or True:
```

`or True` 意味着任何 Researcher 异常都会让 Supervisor 直接结束。配合
`asyncio.gather` 的默认行为，一个子任务失败可能阻止其他成功结果进入 State。
这将作为 Day 5 的直接修复目标。

### 8.2 本地 Qwen 上下文上限未登记

vLLM 配置为 16,384 Token，但 `MODEL_TOKEN_LIMITS` 没有
`openai:qwen3-14b-local`。Writer 超限后可能无法确定截断起点。后续应把模型
上下文上限变成配置，而不是只维护静态表。

### 8.3 无搜索也能“运行”

`SEARCH_API=none` 时，`get_all_tools` 仍返回：

- `ResearchComplete`
- `think_tool`

所以 Researcher 不会因工具列表为空而失败，但也没有外部事实来源。Day 1
成功 Trace 证明的是图和模型兼容，不是检索或引用可靠。

### 8.4 `raw_notes` 尚未被 Writer 使用

主图保留 `raw_notes`，Writer 只消费 `notes`。后续 Evidence 数据模型需要明确
Raw Notes 的持久化位置，避免长文本持续放在 LangGraph State。
