## 4. 标注方法

每行标注一个可独立判断的 Claim，字段包括：

- `claim_id`、`case_id`、Claim 原文；
- 报告给出的 `citation_url`；
- 是否有引用、精确目标是否存在；
- 引用是否直接支持 Claim；
- 事实、时间、数字和范围是否正确；
- 一个或多个结构化错误类型；
- 人工核验使用的原始/官方 `evidence_url`；
- 简洁判定说明。

严格规则：

1. 只有原始论文或官方文档直接支持才算 `supported`；
2. URL 存在但主题无关，只计来源目标存在，不计 Precision；
3. 引用路径404，即使事实碰巧正确，也不计 Precision；
4. 部分支持不按“半分”计算，避免样本少时主观权重放大；
5. 同一 Claim 可以同时有时间、范围和错误来源等多个标签。

### 6.1 Precision 与 Coverage 为什么差距大

28/32条 Claim 带有引用外观，所以 Coverage 很高。但只有6条引用由精确来源直接
支持。失败引用包括：

- 指向无关的 arXiv 论文；
- 模型拼出的 `docs.langgraph.com` 路径；
- 已404的 NIST CSRC 项目路径；
- OWASP 旧站锚点；
- 泛化主页而非支持具体 Claim 的页面。

### 6.2 “平均来源数”为什么不能单独使用

每份报告平均抽取4.12个 URL，但精确目标有效率只有50%。`baseline-008` 一份报告
生成12个 OWASP 锚点，抽查均404；它会显著抬高平均来源数，却没有增加证据。

## 7. 关键错误样例

### 7.1 RAG

- 把原始论文编号写成 `2007.01527`，实际是量子物理论文；
- 把 DPR 写成 BM25；
- 把端到端训练写成分别训练；
- 事实正确的 BART 结论也由错误论文“支持”。

### 7.2 Qwen3 与 NIST

- 当前日期已是2026年，仍称2025年发布的 Qwen3 信息未公布；
- Qwen3 官方尺寸、Hybrid Thinking 和 Apache 2.0 全部被漏掉；
- AI RMF 1.0 日期从2023-01-26错成2023年11月；
- GenAI Profile 日期从2024-07-26错成2024年1月；
- GOVERN/MAP/MEASURE/MANAGE 被替换为模型自创的四项分类。

### 7.3 LangGraph、pgvector 和 OWASP

- LangGraph 示例使用不存在的类和方法；
- pgvector 示例包含无效 `=>` 语法并遗漏多个距离算子；
- OWASP 风险名称基本正确，但引用路径与部分缓解项由模型生成；
- Vector/Embedding 风险被解释为泛化的“向量敏感”，遗漏权限泄露、反演和投毒。

## 8. 运行链路错误

Day3 指标显示所有用例：

1. Supervisor 请求一个 Researcher；
2. Qwen 在 `SEARCH_API=none` 下仍生成 `tavily_search` Tool Call；
3. 工具映射中不存在该工具；
4. Researcher 没有进入 `compress_research`；
5. Supervisor 当前 `or True` 异常分支提前结束；
6. Writer 仍生成最终报告；
7. 根图返回“有报告”的成功状态。

因此 Day4 不能只评价报告文本，还必须评价执行完整性。Runner 的 `degraded` 标志
用 `compression_count < researcher_count` 捕捉这一状态。

## 9. 三个最高优先级问题

### P0：失败隔离和完成状态

- 移除 `or True`；
- 未知工具进入结构化错误；
- 保存部分成功；
- `success/partial/failed` 分开；
- 没有研究笔记时 Writer 不得宣称完整研究成功。

直接进入 Day5。

### P1：来源必须由系统注册

- Writer 不能自由生成 URL；
- 搜索结果先转 SourceRecord；
- 检查 URL、标题、日期、内容类型和哈希；
- 引用使用 Source ID。

对应 Day8、Day13、Day14。

### P2：Claim–Evidence 验证门

- Claim 关联可定位 Evidence；
- 分别验证支持关系、数字、时间和范围；
- 不支持 Claim 修订或删除；
- Writer 只消费验证通过的 Claim。

对应 Day9、Day10、Day26～Day28。
