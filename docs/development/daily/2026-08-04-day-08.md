## 3. 实现内容

### 3.1 可解释证据质量策略

新增 `EvidenceQualityPolicy`，对 PDF 提取块执行确定性检查。

硬拒绝信号包括：

- 文本过短；
- 缺少页码；
- 参考文献章节；
- 典型参考文献条目；
- 只有标题、没有完整句子；
- 可读字符密度过低。

软评分信号包括：

- 缺少章节；
- 章节疑似页眉；
- 段落较短；
- 没有句末标点；
- 词项多样性过低。

`QualityFilteredRetriever` 会先扩大候选集，再过滤明确噪声，并在最终
`SearchResult` 中保留 `quality_score`。过滤原因使用公开安全的代码，不在评测
汇总中复制论文正文。

### 3.2 BM25 + Dense + RRF

实际 CLI 不再只调用 pgvector Dense：

```text
query
  ├─ Qwen query embedding → PostgreSQL/pgvector Dense ─┐
  └─ accepted corpus → BM25 Sparse ─────────────────────┤
                                                        ▼
                                             weighted RRF fusion
```

RRF 只融合排名，不直接比较余弦相似度和 BM25 的不同量纲。Dense/Sparse 的原始
rank 与 score 会继续保存在结果中，便于排查每个候选来自哪一路。

### 3.3 本地 Qwen 二阶段重排

`OpenAIRerankProvider` 调用现有本地服务的 `/rerank` 接口。没有下载第二个模型，
也没有创建第二套 Python 环境。当前 Qwen pooling 模型同时承担：

- 文档向量；
- 查询向量；
- 候选 query-document 相关性重排。

`RerankingRetriever` 对 RRF 返回的扩展候选做二阶段打分，按
`reranker_score` 重新排序后只返回 Top-K。服务响应会检查索引范围、候选数量和
分数类型，异常不会静默转成看似正确的排序。

### 3.4 三种检索模式

`search` 和 `research` 统一支持：

| 模式 | 用途 |
| --- | --- |
| `dense` | pgvector Dense 基线与消融 |
| `hybrid` | 质量过滤后的 Dense + BM25 + RRF |
| `hybrid-rerank` | 在 Hybrid 候选上增加本地 Qwen 重排，默认模式 |

示例：

```bash
.venv/bin/python -m scholarmind.cli search \
  "<ACADEMIC_QUERY>" \
  --retrieval-mode hybrid-rerank \
  --top-k 8
```

development，而 42 道问题属于 test，两者论文 ID 交集为 0。

这验证了此前的 split 防泄漏设计正常工作。为进行最终持出集诊断，CLI 新增显式


### 3.6 PDF NUL 字符修复

第一次 test 索引发现 5 个正文和 3 个章节字段含 PDF 提取产生的 NUL 字符。
PostgreSQL JSONB 不接受 `\u0000`，因此索引结构化失败并留下中断记录，没有把
异常批次标成成功。

原适配器已能清理正文，但没有清理 `EvidenceLocator.section`。本次补充：

- 清理 section 中的 NUL；
- 清理后为空则回退到 `unknown`；
- 在 metadata 的 `sanitization` 中记录移除数量；
- 保留正文清理时的原始内容哈希审计信息；
- 增加章节 NUL 回归测试。

修复后从进度记录恢复，4,026 条全部成功。

## 4. Silver 检索评测

脚本 `scripts/evaluate_paper_retrieval.py` 读取私有问题，但输出产物只包含
question ID、rank、计数、耗时和聚合指标，不写入问题、答案、证据正文、论文标题
或凭据。

运行方式：

```bash
.venv/bin/python scripts/evaluate_paper_retrieval.py \
  --questions "<DATASET_DIR>/evaluation/questions.silver.jsonl" \
  --output "<PRIVATE_OUTPUT_JSON>" \
  --top-k 8
```

42 题结果：

| 指标 | Dense | Hybrid | Hybrid + Rerank |
| --- | ---: | ---: | ---: |
| Source Recall@8 | 100.00% | 97.62% | 100.00% |
| Page Recall@8 | 76.19% | 59.52% | 73.81% |
| Exact Recall@8 | 33.33% | 19.05% | 30.95% |
| Source MRR | 0.9821 | 0.6706 | 0.9601 |
| Page MRR | 0.5401 | 0.3575 | 0.5214 |
| Exact MRR | 0.1730 | 0.0734 | 0.1245 |
| Top-8 质量拒绝率 | 4.46% | 0% | 0% |
| 平均耗时 | 0.167 s | 0.143 s | 0.205 s |

解释：

1. 纯 RRF Hybrid 的正确证据排序明显弱于 Dense，不能单独作为默认模式；
2. 本地 Qwen 重排显著修复了 RRF 的排序，Source Recall 恢复到 100%；
3. Hybrid + Rerank 的 Page Recall 与 Dense 相差 2.38 个百分点，同时清除了最终
   Top-8 中的明确噪声；
4. 逐题比较只有 1 题出现 Dense 命中而 Hybrid + Rerank 未命中；
5. 42 条标签中 41 条能精确映射到 chunk；其中 38 条通过质量门，3 条是标题式或
   非完整句子的 Silver 证据，另 1 条无法精确映射；
6. 不为追求 Silver 分数放宽生产质量门，这 4 条应进入人工复核；
7. 因标签尚未人工确认，上表是工程诊断，不是可对外宣称的正式模型成绩。

因此保留 `hybrid-rerank` 为默认，保留 `dense` 作为可切换基线。
