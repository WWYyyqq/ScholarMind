## 3. Docker Desktop 排障

### 3.1 排除项

依次排除了磁盘容量不足、非 NTFS、项目代码错误、单个 Docker AI 开关、仅由
4.85.0 引起的版本回归、第三方杀毒拦截，以及 Docker 数据目录已有重要数据。
故障时 D 盘 Docker WSL 目录只有刚初始化的小型空白虚拟磁盘。

### 3.2 处理过程

1. 备份 Docker 设置；
2. 下载官方 Docker Desktop 4.84.0 安装包并校验 SHA-256；
3. 从 4.85.0 降级到 4.84.0；
4. 保持 WSL2 后端和 D 盘数据根目录；
5. 关闭不需要的 Docker AI、Inference 和 MCP Toolkit；
6. 清理 Docker 退出后遗留的 0 字节临时套接字；
7. 发现 Windows 已连续运行约 140 小时，并积压大量重启后文件操作；
8. 完整重启 Windows，再启动 Docker Desktop。

### 3.3 结论

重启后 Docker Desktop 4.84.0 正常运行，Linux Engine 29.6.2 可响应。根因最符合
“长时间 Windows/WSL 会话中的套接字重解析点状态未完全释放”，而不是项目代码、
磁盘空间或 GitHub 登录问题。

## 5. Qwen3 Embedding 服务

### 5.1 组件关系

- Qwen3-Embedding-0.6B 把文本映射为语义向量；
- vLLM 加载模型并提供 OpenAI 兼容 API；
- pgvector 保存向量并计算相似度；
- File Researcher 建立 Claim、Evidence、Citation 关系。

Embedding 模型不负责撰写最终长报告，也不是 Qwen3-14B 生成模型。

### 5.2 配置和验收

- 模型权重位于 D 盘，约 1.2 GB，不进入 Git；
- API 仅监听 `[::1]:8001`；
- 服务模型名：`qwen3-embedding-0.6b-local`；
- 向量维度：1024；
- GPU 显存利用率上限：0.15；
- 权重实际占用约 1.12 GiB；
- 通过 `SCHOLARMIND_VLLM_ENV` 复用 ScholarMind 专用 vLLM 环境。

Smoke test：

```text
PASS local embeddings: dimension=1024, relevant=0.6830, irrelevant=0.5237
```

相关文本相似度高于无关文本。访问 IPv6 回环 API 时需确保 `::1` 绕过系统代理。

## 7. File Researcher 真实质量修复

### 7.1 暴露的问题

首次真实报告虽然引用链完整，但机械选取段落首句，发布了 `III.`、参考文献条目、
小写断句残片和与问题相关度较低的句子。

### 7.2 修复

将 ExtractiveClaimGenerator 升级为 query-aware extractive selector：

1. 拆分证据中的完整句；
2. 按问题词项重合度排序；
3. 优先包含 method/model/detection 等方法信号的句子；
4. 过滤短标题、罗马数字标题、参考文献编号、作者条目与小写断句残片；
5. 只返回证据原句，不改写、不补充；
6. ClaimVerifier 继续执行严格抽取式匹配。

修复提升了可读性，但没有降低“声明必须能在证据中逐字定位”的发布门。相同问题
重跑后保留 4 条完整证据句，并附带论文标题和页码。
