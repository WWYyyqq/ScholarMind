## 3. 本轮为什么先做 Agent/API

Day 8 结束时已经具备：

```text
PostgreSQL/pgvector Dense
        + BM25
        + weighted RRF
        + evidence quality gate
        + local Qwen reranking
        → File Researcher
        → Claim Verifier
        → page-level Citation
```

但实际入口仍集中在 `cli.py` 的私有函数中。若直接增加界面或新 Researcher，会
产生第二套数据库、检索器和资源关闭逻辑。面试演示也只能展示命令行，不能展示
真正可调用的 Agent。

因此本轮先抽出公共服务，再让 CLI 和 LangGraph API 复用它。LangGraph Server
已经提供 HTTP API、运行管理和 Studio，不额外引入 FastAPI 依赖。

## 4. 实现内容

### 4.1 `ScholarMindResearchService`

新增 `src/scholarmind/service.py`，集中管理：

- `EmbeddingRuntime`；
- Qwen OpenAI-compatible Embedding Provider；
- Dense / Hybrid / Hybrid+Rerank 三种检索组装；
- PostgreSQL Repository；
- Source 元数据加载；
- File Researcher；
- Reranker HTTP Client 与数据库连接的生命周期；
- Embedding OpenAI Client 的显式释放；
- Evidence、Claim、Verification、Citation 序列化。

服务支持上下文管理器，初始化中途失败时也会关闭已经打开的 Repository、
Embedder 和 Reranker；重复调用 `close()` 不会重复释放资源。

### 4.2 CLI 复用公共服务

`scholarmind research` 不再自行连接数据库、组装 Retriever、加载 Source 和关闭
Reranker。CLI 只负责解析参数与展示结果，实际研究调用统一进入
`ScholarMindResearchService`。

索引和搜索命令仍保持原有命令行兼容；检索器构造已经委托给公共
`build_retriever()`，避免 Agent 与 CLI 的权重或质量门逐渐不一致。

### 4.3 ScholarMind LangGraph

新增 `src/scholarmind/graph.py`，公开图变量：

```text
scholarmind_researcher
```

输入：

```json
{
  "question": "research question",
  "retrieval_mode": "hybrid-rerank",
  "top_k": 5
}
```

输出字段：

- `status`：`success / partial / failed`；
- `publication_ready`；
- `report`；
- `evidence / claims / verifications / citations`；
- `errors`：阶段、错误码、说明、可恢复性；
- `counts`：Evidence、Claim、已发布 Claim 和 Citation 数量。

请求为空、模式非法或 `top_k` 越界时，在打开数据库前返回配置失败。数据库、
Embedding 或 Reranker 不可用时返回可恢复的服务失败。异常信息不会回传 DSN、
密码或 API Key。

### 4.4 LangGraph Server 注册

以下两个配置均新增 `ScholarMind Researcher`：

- `langgraph.local.json`：本地无 Supabase Auth；
- `langgraph.json`：保留部署 Auth。

现在同一个 Server 可选择：

1. `Deep Researcher`：上游兼容的 Web/Baseline 图；
2. `ScholarMind Researcher`：本地论文证据优先图。

两图暂不强行合并，便于隔离故障和进行消融。
