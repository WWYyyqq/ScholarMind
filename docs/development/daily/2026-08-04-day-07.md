Evidence 已全部使用本地 Qwen Embedding 生成向量并写入 pgvector；第二次执行会

下一阶段任务，不能把当前结果描述为已经达到生产级检索质量。

## 2. 开始状态

开始本日工作前：

- PR #7 已合并到 `main`，合并 Commit 为 `59ffa0c`；
- 论文数据管线可稳定产出 49 个 Source 和 6,853 条 Evidence；
- PostgreSQL/pgvector、本地 Embedding 服务和 32 条小规模索引已经验证；

## 3. 设计目标

本次改造遵循四个原则：

1. 数据库是完成状态的唯一事实来源，JSONL 只用于人类审计；
2. 只有模型名和 Evidence 内容哈希都匹配时，向量才算有效；
3. 单条可定位的数据错误允许隔离并继续，服务或数据库错误必须快速失败；
4. 日志不保存论文正文、数据库密码、API Key 或个人目录。

## 4. 实现内容

### 4.1 默认断点续跑

`EvidenceIndexer.index()` 新增：

- `resume`：读取当前模型下有效的 Evidence ID，跳过已完成项；
- `continue_on_error`：隔离单条数据错误并保留结构化失败信息；
- `on_progress`：每批上报请求数、完成数、跳过数和失败数；
- `IndexingResult.complete`：明确区分完整成功与部分成功。

CLI 默认启用 resume。需要重新计算时使用 `--force-reindex`，需要首错即停时使用
`--fail-fast`。

### 4.2 内容哈希防止陈旧向量

embedding 表新增 `content_sha256`。写入向量时同时保存 Evidence 的正文哈希；
读取已完成 ID 和 Dense Search 时都会排除哈希不匹配的旧向量。

因此，Evidence 正文变化后无需手工删除旧数据：下一次索引会自动重算，查询也不会
在重算前返回陈旧向量。

### 4.3 批量写入

PostgreSQL Repository 新增 Source 和 Evidence 的批量 upsert。此前每条 Evidence
都会单独打开事务；现在按批使用 `executemany`，减少 6,853 条数据导入时的数据库
往返。

### 4.4 结构化进度日志

新增 `JsonlIndexingProgressRecorder`，记录：

- `run_started`；
- 每批 `batch_progress`；
- `run_completed`；
- `run_interrupted`。

每次运行都有独立 UUID 和 UTC 时间戳，并在追加后执行 flush/fsync。默认文件位于
数据集的 `.scholarmind/index-<model>.jsonl`。

### 4.5 失败分类

批次遇到可定位的 `ValueError` 时，索引器使用二分方式缩小范围，直到找出单条坏
Evidence。该条记录进入结构化 failures，其余记录继续。

网络异常、Embedding 服务退出、数据库连接失败等系统性异常不会递归拆批，而是
立即停止。这样既保留部分进度，也避免服务故障时产生大量无意义重试。

### 4.6 PDF 文本 NUL 清理

首次全量写入暴露出 PostgreSQL text 不接受 NUL 字符。检查确认共有 7 条解析记录
包含转义后的 NUL。适配器现在会：

1. 在入库前确定性移除 `\\x00`；
2. 重新计算清理后的 `content_sha256`；
3. 在 metadata 中记录移除数量和原始哈希；
4. 若清理后正文为空，则明确报数据错误。

清理过程可审计，不会静默改变哈希含义。

## 5. 真实运行结果

### 5.1 分阶段恢复验证

先从已有 32 条向量继续：

- 跳过：32；
- 新增：16；
- 结果：48 条全部有效。

再次运行 48 条时全部跳过。随后使用 batch size 64 扩展到 112 条，再次运行仍能
稳定跳过已有记录。

### 5.2 全量索引

修复 NUL 边界后执行论文全集：

| 指标 | 结果 |
| --- | ---: |
| 请求 Evidence | 6,853 |
| 本轮新建向量 | 6,741 |
| 从数据库恢复/跳过 | 112 |
| 失败 | 0 |
| 完整状态 | true |
| 耗时 | 248.831 秒 |
| 向量维度 | 1024 |

随后立即重跑：

| 指标 | 结果 |
| --- | ---: |
| 新建向量 | 0 |
| 恢复/跳过 | 6,853 |
| 失败 | 0 |
| 完整状态 | true |
| 耗时 | 14.030 秒 |

这证明断点续跑不是只由进度文件模拟，而是由数据库中的模型名和内容哈希实际判断。

### 5.3 数据库核验

直接查询数据库得到：

- Source：50；
- Evidence：6,855；
- 当前 Qwen 模型的有效向量：6,853；
- 陈旧向量：0。

其中多出的 1 个 Source 和 2 条 Evidence 来自 Repository 集成测试，使用独立测试
模型，不会进入本地 Qwen 检索结果。真实论文数据本身仍为 49 / 6,853。

### 5.4 语义检索与 File Researcher

使用“多变量时间序列异常检测与根因分析方法”类问题进行真实检索，前列结果包含
MTAD-GAT、TranAD 和 BARO 等相关论文，证明本地向量链路确实返回语义相关内容。

File Researcher 也能生成带页码 Citation 且通过现有发布门的结果。不过结果中出现
两类质量问题：

- 过短的章节标题被当作 Evidence；
- 参考文献标题被当作正文证据；
- 个别 PDF 抽取片段在词边界处不完整。

这些问题不会影响“索引可靠性已完成”的结论，但会影响回答质量。下一阶段必须用
语料过滤、Sparse Retrieval、RRF 和 Reranker 解决。
