## 5. Runner 设计

### 5.1 CLI

完整运行：

```bash
.venv/bin/python scripts/run_baseline.py \
  --run-id day3-qwen3-local-20260731 \
  --output evaluation/results/day3-qwen3-local-20260731.jsonl
```

单用例：

```bash
.venv/bin/python scripts/run_baseline.py \
  --run-id day3-qwen3-local-20260731 \
  --output evaluation/results/day3-qwen3-local-20260731.jsonl \
  --case-id baseline-001
```

只验证用例：

```bash
.venv/bin/python scripts/run_baseline.py --dry-run
```

### 5.2 稳定 ID

- `case_id`：人工定义，跨运行稳定；
- `run_id`：表示一组实验配置，由 CLI 明确指定；
- `attempt`：同一 run/case 内递增；
- `thread_id`：由 run/case/attempt 通过 UUID5 确定；
- `record_id`：由 ScholarMind/run/case/attempt 通过 UUID5 确定；
- `graph_run_id`：来自 LangGraph 根事件。

### 5.3 追加与续跑

Runner 启动时解析已有 JSONL，找出当前 `run_id` 已记录的 `case_id`。每个结果单独
以追加模式写入并同步到磁盘。没有 `--rerun` 时绝不改写历史行；有 `--rerun` 时
也只新增 attempt。

### 5.4 指标采集

LangGraph `astream_events(version="v2")` 提供：

- 节点开始/结束和节点耗时；
- 根 Run ID；
- LLM 调用数；
- 模型请求的 Tool Call；
- 实际进入 LangChain Tool 的调用；
- 事件错误。

事件流的 OpenAI 使用量在当前版本中为空，因此 Token 不使用字符数估算。Runner
在每个串行用例前后读取本地 vLLM `/metrics`：

```text
vllm:prompt_tokens_total
vllm:generation_tokens_total
```

两个 Counter 的差值是该用例的真实输入和输出 Token。串行执行保证没有其他用例
并发污染差值。

工具指标区分：

- `by_name`：模型请求的工具；
- `executed_by_name`：真正开始执行的工具；
- `requested_search`：模型请求的搜索；
- `search`：实际执行搜索。

这一区分在 Day4 证明非常重要。

## 6. JSON Schema

新增 `evaluation/schemas/baseline_result.schema.json`，Schema 版本为 `1.0.0`。

主要结构：

```text
identity
  schema_version / record_id / run_id / case_id / attempt
execution
  status / started_at / completed_at / thread_id / graph_run_id
configuration
  model / search / concurrency / iteration budgets / base_url
metrics
  latency / node counts / node latency / tokens / tools / sources
artifacts
  source_urls / final_report / error
```

配置不记录 API Key。

## 7. 真实运行与调试记录

启动 Qwen3：

```bash
./services/local-llm/start.sh
```

冷启动约2分23秒。本轮实测权重9.44 GiB、KV Cache约10.77 GiB，服务正常监听
`[::1]:8000`。

`baseline-001` 的历史 attempt 全部保留：

| Attempt | 现象 | 根因与处理 |
| ---: | --- | --- |
| 1 | 54秒后502 | Shell 继承 HTTP/HTTPS Proxy，`NO_PROXY` 为空；本地请求被代理转发 |
| 2 | `token_usage=None` 属性错误 | 结构化输出事件允许空使用量，增加兼容处理 |
| 3 | 报告成功但 Token=0 | 事件流路径不返回 usage，拒绝用字符数假装 Token |
| 4 | vLLM Counter 差值成功 | 精确记录输入/输出 Token |
| 5 | 请求搜索和实际搜索分离 | 发现 `ConductResearch` 名称也包含 search 子串并修正 |
| 6 | 最终 Schema | 增加 Compression 和 `degraded` 派生状态 |

Runner 现在自动把 `127.0.0.1`、`localhost`、`::1` 加入大小写两种
`NO_PROXY`，不修改用户全局代理配置。
