### 4.7 接入 OpenAI 兼容本地 API

在 `Configuration` 中加入可选 `openai_base_url`，并在所有
`openai:` 模型角色初始化时传递 `base_url`：

- Research Model
- Summarization Model
- Compression Model
- Final Report Model

本地 `.env` 采用以下非敏感配置模式：

```dotenv
OPENAI_API_KEY=local
OPENAI_BASE_URL=http://[::1]:8000/v1
RESEARCH_MODEL=openai:qwen3-14b-local
SUMMARIZATION_MODEL=openai:qwen3-14b-local
COMPRESSION_MODEL=openai:qwen3-14b-local
FINAL_REPORT_MODEL=openai:qwen3-14b-local
SEARCH_API=none
MAX_CONCURRENT_RESEARCH_UNITS=1
MAX_RESEARCHER_ITERATIONS=2
MAX_REACT_TOOL_CALLS=4
```

这里的 `OPENAI_API_KEY=local` 只是 OpenAI 客户端要求的本地占位值，不是
真实凭据；`.env` 本身未提交。

### 4.9 修复本地 LangGraph 认证阻塞

首次直接使用上游 `langgraph.json` 启动后，Server 能加载图，但普通本地 API
请求返回：

```text
401 Authorization header missing
```

根因是上游配置启用了 `src/security/auth.py` 的 Supabase JWT 认证，而本地
开发环境按安全要求没有配置 Supabase 凭据。

解决方案是新增 `langgraph.local.json`：

- 保留相同的图入口、Python 版本、依赖和 `.env`；
- 仅移除本地开发不需要的 `auth` 块；
- 原 `langgraph.json` 不变，继续用于需要认证的部署场景；
- 增加单元测试，保证本地配置没有认证、部署配置仍保留认证。

## 5. 问题、根因与解决方案

| 问题 | 现象与证据 | 根因 | 解决方案 | 状态 |
| --- | --- | --- | --- | --- |
| WSL IPv4 回环不可用 | vLLM 显示监听 `127.0.0.1`，连接仍被拒绝 | 当前 WSL mirrored networking 环境的 IPv4 回环行为异常 | 只监听 IPv6 回环 `::1`，API 改为 `http://[::1]:8000/v1` | ✅ 已解决 |
| Qwen 工具调用 JSON 截断 | 开启 thinking 时工具参数无法稳定解析 | 思考输出占用响应并干扰当前 vLLM 工具调用格式 | 全局设置 `enable_thinking=false`，Hermes 解析器测试通过 | ✅ 已解决 |
| 模型冷启动较慢 | D 盘两个分片加载约 3.5～4 分钟 | 模型位于 WSL 的 9P 挂载盘 | 保留 D 盘以保护 C 盘容量，并在文档中明确等待标志 | ⚠️ 接受 |
| LangGraph API 返回 401 | `Authorization header missing` | 上游配置强制 Supabase JWT | 新增无认证的 `langgraph.local.json`，保留部署认证配置 | ✅ 已解决 |
| C 盘空间突然减少 | 可用空间一度下降到约 34 GB；`pagefile.sys` 当时约 33.94 GB | Windows 系统管理页面文件响应 WSL/vLLM 的高内存提交自动扩张 | 停止 vLLM/LangGraph；建议不用时关闭 WSL，模型和缓存继续留在 D 盘；不直接删除页面文件 | ⚠️ 需持续观察 |
| pytest 默认捕获异常 | 并行质量命令中捕获临时文件消失 | 当次临时文件/捕获环境异常，不是测试失败 | 使用 `pytest -s` 独立重跑，4 个测试通过 | ✅ 已解决 |
| 全量 mypy 不能直接通过 | 上游包缺少类型桩并触发 LangSmith 客户端内部检查错误 | 上游尚无完整可用的 mypy 工程配置 | Day 1 对新增测试做定向 mypy；全项目配置留到 Day 6 工程质量建设 | ⏳ 已记录 |
