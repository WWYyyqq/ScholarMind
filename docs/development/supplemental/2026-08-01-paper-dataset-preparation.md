# 2026-08-01：本地论文数据集预处理

## 今日目标

把个人论文目录中的 97 个 PDF 整理成可追溯、可重复构建的数据集基线，完成以下四项工作：

1. 精确去重并归并同一逻辑作品；
2. 建立包含全部来源记录的 manifest；
3. 完成版面感知解析与可回溯切块；
4. 建立与开发数据隔离的评测集，并明确 silver 与 gold 的边界。

本工作属于数据准备专项，不代表新的模型能力已经实现，也不把机器抽取的评测答案包装成人工 gold 标注。
它不改变 42 天路线图的 Day 编号，也不代表计划中的 Day 5“隔离子研究任务失败”已经完成。

## 安全边界

- 原论文目录按只读输入处理，不执行删除、改名、移动或格式转换。
- 仅扫描 `.pdf`；目录中的 Word、Excel 和其他格式不进入数据集。
- 97 个 PDF 全部保留在文件级清单中；所谓去重是逻辑去重，不是删除原文件。
- 生成目录不复制 PDF，只保存 JSON/JSONL 元数据、版面结构、切块和评测草案。
- Git 只跟踪脚本、测试、Schema 和文档；原论文、生成数据及私有人工标注留在仓库外。
- 产物不序列化本地绝对路径，只记录相对路径和稳定标识。

## 设计与实现记录

### 1. 去重和身份模型

- 对每个 PDF 流式计算完整 SHA-256；不依赖文件名或文件大小做精确去重。
- 定义稳定的 `file_id`、`paper_id` 和 `work_id`：
  - `file_id` 绑定相对路径；
  - `paper_id` 绑定唯一 PDF 内容；
  - `work_id` 绑定逻辑论文作品。
- 选择规范文件时优先普通研究目录中的路径，并降低 baseline 副本优先级；规则完全确定，重复执行可得到相同选择。
- 精确重复文件以 `duplicate_of_file_id` 指向规范文件；所有别名仍保留在 `manifest.jsonl`。
- 使用规范化文件名和已核验别名连接翻译版与原文；翻译关系记录为 `translation_of_paper_id`。
- 已识别但二进制不同的同作品版本共享 `work_id`，避免开发/测试泄漏。

### 2. Manifest

- 文件级 manifest 保存相对路径、SHA-256、页数、标题、语言、文档类型、类别、年份、重复关系、作品关系、解析状态和数据划分。
- 规范 manifest 每个唯一内容只保留一条记录，用作解析入口。
- 标题选择优先级为：首页版面标题、可信 PDF metadata、清洗后的文件名。
- 年份只从首页明确日期提示中推断，不把收藏目录的年份当作出版年份。
- 增加 JSON Schema，约束标识、哈希、页数、路径、重复关系和划分字段。

### 3. 版面解析和切块

- 使用项目现有的 PyMuPDF 依赖，不新增全局环境或额外解析服务。
- 每页保留页面尺寸、旋转角度、文本块、图片块和字符数。
- 文本块保留边界框、粗粒度栏位、阅读顺序、字体、字号、粗体、标题和重复页眉/页脚标志。
- 切块限制在单页内；每块保留页码、章节名、块顺序、合并边界框、内容哈希和前后链接。
- 若整篇可提取文本少于安全阈值，流程显式报错为需要 OCR，避免静默产生空文档。
- 当前不重建表格、公式和图像语义，解析器 warning 会把这一限制写入文档 JSON。

### 4. 隔离评测

- 以 `work_id` 为最小划分单位，防止同一论文的副本、翻译或版本跨越开发集与测试集。
- 默认从英文原文中按类别轮询、确定性地选择 24 个逻辑作品作为测试集。
- 测试记录设置 `tuning_allowed: false`，明确禁止用于参数或提示调优。
- 开发索引与评测检索语料物理分开：前者只读 `chunks.development.jsonl`，后者只读 `evaluation/corpus.chunks.jsonl`；全量 `chunks.jsonl` 仅用于审计。
- 自动生成两类抽取式问题：摘要证据、方法/背景章节标题定位。
- 每题保存页码、`block_ids`、PDF 坐标、0–1 左上角归一化坐标和原文证据；答案必须能从这些版面块逐字回查。
- 全部自动题标记为 `silver_extractive` 与 `machine_generated_pending_human_review`；未经过人工复核前不命名为 gold。

9. silver 问题没有被误标为 gold；
10. 输出目录不包含 `.pdf` 文件。

## 已知限制与风险

- 规则型标题、年份、类别和章节识别会有误差，尤其是复杂首页、扫描件和非标准双栏版式。
- 哈希只能识别二进制完全相同的副本；预印本和出版版的作品归并仍需语义或人工核对。
- PyMuPDF 能保留块级几何，但不能自动恢复可靠的表格单元格、数学公式语义和图表含义。
- 当前 silver 题型窄，主要验证抽取和证据定位链路，不代表 ScholarMind 的完整问答能力。
- 机器抽取答案虽已保证可从标注版面块回查，但仍可能过短、问题表述不自然或选择错误章节，必须人工复核后才能形成正式基准。

## 后续人工标注计划

逐题操作、题型判定、错误代码、两轮复核、冲突裁决与 Gold 导出规则已经整理到 [Silver → Gold 人工标注手册](../../evaluation/paper-dataset/silver-to-gold.md)，后续实际操作以该手册为准。

1. 对测试集 24 篇作品逐篇确认标题、作品归并和测试隔离是否正确；
2. 对每道 silver 题进行“保留、修改、删除”判定，并记录原因；
3. 补充事实、数值/表格、跨段综合、论文比较和不可回答题；
4. 采用第二人复核或至少间隔复核，解决证据边界和答案唯一性争议；
5. 生成独立版本的 gold 数据及标注说明，禁止写入公开仓库中的真实私有内容；
6. 在后续回归中分别报告检索召回、答案正确性、引用覆盖率和引用精度，避免只看“是否生成报告”。

## 今日结论

本专项建立的是数据工程基线：不破坏原始论文、不重复存储 PDF、保留来源追踪，并把开发与评测从作品层面隔离。自动评测数据目前只具备 silver 级别，实际构建与版面抽查已经通过；下一阶段重点是人工复核并形成 gold 标注，而不是直接用自动结果宣称模型达到正式评测水平。
