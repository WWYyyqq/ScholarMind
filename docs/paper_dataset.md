# 本地论文数据集预处理说明

本文档说明如何把个人论文目录整理成 ScholarMind 可用、可追溯且不会污染原始资料的数据集。当前语料范围固定为 **97 个 PDF 文件**；Word、Excel 及其他格式不进入本流程。

## 处理目标与边界

- 原始论文目录只读：脚本只扫描、读取和计算哈希，不改名、不移动、不删除，也不回写任何文件。
- 全部 97 个 PDF 都保留在文件级清单中，保证来源记录完整。
- 输出目录不复制 PDF，只保存清单、解析后的 JSON、检索块、重复关系和评测草案，因此不会再产生一份论文副本。
- 个人机器上的绝对路径不写入数据集或仓库；清单仅保存相对于输入根目录的路径。
- 当前盘点结果为：**97 个 PDF 文件、85 份唯一 PDF 内容、58 篇逻辑作品**。三种数量对应不同层级，不能混用。

| 层级 | 数量 | 含义 |
| --- | ---: | --- |
| 文件记录 | 97 | 用户目录中实际存在的 PDF；包含重复副本和翻译版 |
| 唯一内容 | 85 | 按完整文件 SHA-256 精确去重后的 PDF 内容 |
| 逻辑作品 | 58 | 把同一论文的原文、翻译版和已识别的内容变体归并后的作品数 |

## 四项预处理

### 1. 去重与作品归并

脚本首先为每个 PDF 计算完整 SHA-256，并使用稳定标识区分三个概念：

- `file_id`：一个相对路径对应一个文件记录；
- `paper_id`：一个唯一 PDF 内容对应一个解析对象；
- `work_id`：同一逻辑论文对应一个作品组，可包含原文、翻译和不同 PDF 版本。

精确重复文件不会从原目录删除。每组只选择一个规范文件进行解析，其他副本通过 `duplicate_of_file_id` 和 `canonical_relative_path` 指向规范记录。翻译版通过 `translation_of_paper_id` 与原文关联。每个唯一内容还带有 `index_policy`：58 个主版本、24 个辅助译文和 3 个跳过的语义版本，共 82 份内容可进入索引。文件级清单仍包含全部 97 条记录，便于审计。

目前的作品归并以规范化文件名和少量已核验别名为基础。它能够处理当前语料中已知的翻译标记、重复目录和少数截断文件名，但它不是通用的论文实体解析器；新增语料后仍需人工抽查 `work_id`。

### 2. 建立可追溯清单

`manifest.jsonl` 记录全部 PDF，包括相对路径、文件哈希、大小、页数、标题、语言、粗粒度类别、原文或翻译属性、重复关系、作品关系、数据划分和解析状态。`canonical_manifest.jsonl` 仅保留 85 条唯一内容记录，`works.jsonl` 汇总 58 篇逻辑作品。

清单中的年份只在论文首页出现明确的版权、发表、接收或 arXiv 日期提示时才填写；目录名中的年份不会被误当作出版年份。类别、语言和标题均由规则自动推断，属于可复核元数据，而非人工金标准。

### 3. 版面感知解析与切块

每份唯一 PDF 使用 PyMuPDF 解析为结构化 JSON：

- 按页记录宽度、高度和旋转角度；
- 按文本块记录阅读顺序、边界框、左右栏、字体、字号和粗体信息；
- 记录图片块的边界框和尺寸，但不导出图片二进制；
- 检测重复页眉和页脚，并在切块时跳过；
- 用编号、字号和粗体启发式识别章节标题；
- 切块严格限制在单页内，保留页码、合并边界框、原块顺序、内容哈希以及前后块链接。

边界框使用 PDF 点坐标，坐标原点按 PyMuPDF 的左上角语义记录。当前语料 97/97 都有可提取文本，所以主流程不启用 OCR；若新增 PDF 的可提取文本过少，脚本会停止并提示需要 OCR，而不是悄悄生成空数据。

### 4. 隔离评测集

评测划分以 `work_id` 为单位，避免同一论文的原文、翻译或副本同时落入开发集和测试集。默认从英文原文中按粗粒度类别确定性地选取 24 篇作品作为 `test`，并把 `tuning_allowed` 设为 `false`；其余记录进入 `development`。物理产物也分开保存：开发建库只能使用 `chunks.development.jsonl`，正式评测检索只能使用 `evaluation/corpus.chunks.jsonl`；`chunks.jsonl` 是包含可索引与跳过版本的全量审计文件，不应直接用于开发建库。

脚本会从摘要和方法/背景章节标题中自动抽取带页码、原始边界框、归一化边界框、`block_ids` 和原文证据的问题。该结果是 **silver（机器生成、待人工复核）**，不是 gold。它只能用于流程冒烟测试、证据定位检查和初始回归，不能作为最终模型质量结论。

正式评测前需要人工完成：

1. 逐题核对问题是否自然、答案是否唯一且被证据完整支持；
2. 修正标题、摘要和章节识别错误；
3. 补充跨段落推理、表格/数值、论文比较和不可回答问题；
4. 至少进行一次独立复核，并记录标注者、版本和争议处理结果；
5. 将通过复核的题目另存为 gold 集，且继续禁止用于提示调优或参数调优。

## 生成物

| 路径 | 内容 |
| --- | --- |
| `manifest.jsonl` | 全部 97 个 PDF 的文件级记录 |
| `canonical_manifest.jsonl` | 85 份唯一 PDF 内容的规范记录 |
| `works.jsonl` | 58 篇逻辑作品的汇总记录 |
| `duplicate_groups.json` | 精确重复组及其规范相对路径 |
| `documents/*.json` | 版面感知的逐页解析结果 |
| `chunks.jsonl` | 11,387 个单页结构化块的全量审计文件（含不可索引版本） |
| `chunks.development.jsonl` | 6,853 个仅供开发建库的可索引块 |
| `evaluation/corpus.chunks.jsonl` | 4,026 个仅供正式评测检索的隔离语料块 |
| `evaluation/papers.jsonl` | 隔离的测试论文清单 |
| `evaluation/questions.silver.jsonl` | 机器生成、待人工复核的评测题 |
| `dataset_config.json` | 本次构建参数，不包含本地绝对路径 |
| `summary.json` | 数量、类别、语言和评测规模汇总 |

生成目录本身应保存在仓库之外。仓库只跟踪构建脚本、Schema、测试和说明文档；真实论文、解析数据和私有评测标注均不提交到 GitHub。

## 运行方式

在项目虚拟环境中执行，输入和输出均使用你自己的路径。首次构建时输出目录应不存在：

```bash
python scripts/prepare_paper_dataset.py \
  --source "<PDF_SOURCE_DIR>" \
  --output "<DATASET_OUTPUT_DIR>" \
  --eval-size 24 \
  --max-chunk-chars 1600
```

需要重新生成时，可添加 `--replace`。脚本会先把旧输出改名为带时间戳的备份，而不是直接删除：

```bash
python scripts/prepare_paper_dataset.py \
  --source "<PDF_SOURCE_DIR>" \
  --output "<DATASET_OUTPUT_DIR>" \
  --eval-size 24 \
  --max-chunk-chars 1600 \
  --replace
```

随后运行独立验证器：

```bash
python scripts/validate_paper_dataset.py \
  --dataset "<DATASET_OUTPUT_DIR>" \
  --schemas evaluation/schemas
```

构建后至少检查以下不变量：

- `summary.json` 中的源 PDF 数为 97、唯一内容数为 85、逻辑作品数为 58；
- `manifest.jsonl` 恰有 97 行，且没有绝对路径；
- `canonical_manifest.jsonl` 恰有 85 行；
- `chunks.jsonl` 恰有 11,387 行，且每块 `char_count <= 1600`、文本长度与 SHA-256 均一致；
- `chunks.development.jsonl` 与 `evaluation/corpus.chunks.jsonl` 互不重叠，并精确组成全部 10,879 个可索引块；
- 同一 `work_id` 只出现一种 `dataset_split`；
- 测试记录全部为 `tuning_allowed: false`；
- 每道 silver 题的答案必须逐字来自其 `block_ids`，原始与归一化边界框必须和这些版面块一致；
- `documents/` 和 `chunks.jsonl` 中的 `paper_id` 均能回连规范清单；
- 评测题仍明确标记为 `machine_generated_pending_human_review`。

## 当前构建结果（2026-08-01）

真实 97 篇 PDF 的最终构建已通过独立验证：85 份唯一内容、58 篇逻辑作品、11,387 个全量块，其中 10,879 个可索引块被物理分为 6,853 个开发块和 4,026 个评测块；24 篇评测论文共产生 42 道待人工复核的 silver 问题。最大块长度为 1,600 字符，超限、字符计数不一致和内容哈希不一致均为 0。输出约 60 MB 且不含 PDF。

## 当前局限

- 双栏文本、普通图片和常见标题可保留版面位置，但表格结构、数学公式、脚注引用关系和图片语义尚未重建。
- 阅读顺序依赖 PyMuPDF 的版面排序及启发式分栏，复杂跨栏图表附近可能需要人工修正。
- 精确去重基于文件哈希；相同论文的重新排版版、预印本/出版版识别依赖 `work_id` 规则和人工复核。
- 标题、语言、年份、类别、标题层级与摘要抽取都是规则推断，不应直接当作人工标注真值。
- 当前 silver 题型只覆盖摘要证据和方法/背景章节定位，不能充分衡量完整的学术问答、综合推理或引用质量。
- 本流程不训练模型，也不要求启动本地大模型；它只准备后续检索、问答和评测所需的数据层。
